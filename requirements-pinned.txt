# Use with: pip install -r requirements-pinned.txt
#
# This file is the lockfile: every package in the resolved dependency
# closure is pinned == to an exact version, direct and transitive alike.
# pyproject.toml holds the abstract spec (version ranges for direct
# dependencies); every == pin in the direct section below lies inside its
# pyproject range (enforced by tests/test_generate_sbom.py). A fresh
# install from this file can therefore never resolve to a different
# version: no upstream release can stale the checked-in SBOM
# (sbom/textforensics.cdx.json) or fail the CI staleness gate on its own.
#
# HOW TO UPDATE (a version bump is a deliberate, reviewed commit):
#   1. Edit the == line(s) for the package(s) to bump. If the new version
#      falls outside the pyproject range, widen the range in pyproject.toml
#      in the same commit, with the release-notes review recorded.
#   2. Fresh venv: python3 -m venv <venv>; <venv>/bin/python -m pip install
#      -r requirements-pinned.txt (TMPDIR inside the repo, PIP_NO_CACHE_DIR=1).
#   3. <venv>/bin/python -m pip freeze > freeze.txt; rewrite the
#      "Transitive (locked)" section from freeze.txt (drop the editable
#      textforensics line); prune lines nothing requires anymore.
#   4. Regenerate the SBOM in the same venv:
#      <venv>/bin/python scripts/generate_sbom.py; commit SBOM + lockfile
#      together. If pre-commit flags the two SBOM SHA properties, update
#      only those two .secrets.baseline entries (see docs/QUALITY_GATES.md).
#   5. Run the gates: claims (33/33), schemas (12 OK), pre-commit (13/13),
#      tests/test_generate_sbom.py.
# Dependabot (pip, weekly, .github/dependabot.yml) proposes bumps as PRs;
# this repo works main-only, so apply them as direct main commits, never
# by merging a PR. The pip-audit gate is the security backstop: a CVE in a
# pinned version fails CI until the pin is bumped.
#
